# FineRove · 研潮

基于 Octop 的 AI 投资工作台，接入驭潮行情与 NEO 核心指标服务。当前处于集成开发阶段，不是已完成的投资终端。

## 本地运行

需要 Python 3.12+、uv、Node.js 与 npm。

```sh
uv sync --frozen
cd dashboard
npm ci
npm run build
cd ..
./start.sh
```

前端构建完成后，在仓库目录使用：

| 操作 | 命令 |
|------|------|
| 后台启动并等待就绪 | `./start.sh` |
| 查看地址、PID 与日志路径 | `./status.sh` |
| 正常停止，保留账号和数据 | `./stop.sh` |

这三个脚本适用于 macOS/Linux，固定监听本机 `127.0.0.1`。重复启动会返回当前进程信息；端口被其他程序占用时会报错，不会终止其他服务。日志、进程状态和锁文件都保存在 FineRove 独立目录中。服务启动失败时按提示查看日志，不要将含口令的完整日志公开。

首次打开 `http://127.0.0.1:8098` 进入初始化向导。**没有固定的管理员账号或登录密码**：使用独立生成的向导口令完成验证后，自行创建账号密码。向导口令文件为 `~/.finerove/octop-login.txt`（沿用底座文件名，但位于独立目录，不复用旧安装口令）。以后登录使用自己设置的账号密码。

账户初始化和启动服务不会自动接通 NEO 私服；未配置计算服务时，指标页会显示未连接，不能计算真实行情。

默认仅监听 `127.0.0.1:8098`，配置、数据库、专家工作区、插件与日志默认放在 `~/.finerove`。启动后按首次配置向导完成自己的账号和模型设置。

`FINEROVE_HOME` 可指定独立存储目录；`FINEROVE_PORT`、`FINEROVE_BIND_HOST` 可调整监听。继承的 `OCTOP_*` 设置会被清除，指向旧 `~/.octop` 的存储别名会被拒绝。不要复用原 Octop 的配置或数据库。这个隔离入口不等于操作系统文件访问沙箱。

```sh
FINEROVE_HOME="$PWD/.finerove" FINEROVE_PORT=8098 uv run finerove run
```

## 看盘与自选

投资研究入口的“看盘与自选”页签复用驭潮原生界面，提供证券搜索、分时与多周期 K 线、多图布局、公共技术指标、自选分组和笔记。其他高级菜单与尚未接入的卡片会明确提示不可用。

默认由 FineRove 直接读取腾讯公开行情并进行短时内存缓存，普通看盘不需要启动 8031，目前不包含完整本地行情历史库和全市场离线筛选。`FINEROVE_MARKET_BASE_URL` 仅用于显式选择旧只读行情适配器，原生分时等扩展接口要求默认内置行情服务。

自选数据和偏好保存在 FineRove 独立控制库中，按实际登录用户隔离；清空列表会保留为空，多会话修改冲突须刷新后重试。不自动读取或上传旧驭潮浏览器存储。

## NEO 核心指标

短线趋势、中线趋势、钱袋子、趋势柱线、主力吸筹、主力成本、核心标模型和六分段属于受保护能力。公开客户端不包含这些公式或模型权重；计算在独立授权的驭潮服务端执行。未配置或未接通的能力不会回退为本地计算，也不会生成演示值冒充结果。

看盘页点击“NEO 趋势柱线”，在单屏或左右布局的沪深 A 股日线副图查看结果。当前图表使用前复权；不计算未收盘当日日线，也不将日线结果复用于周线或分钟线。其余核心指标保持未接通。该迁移公式尚未完成原模型逐点一致性验证。微信、飞书和后台任务仍需完成各自的真实账号验收。

NEO v2 计算接口只接受调用方提供的标准化 OHLCV 快照，不读取驭潮行情库。快照包含完整可用预热序列，输入 SHA-256 指纹绑定签名授权；返回结果的指纹、日期、证券、复权和覆盖范围必须与输入相符。结果附算法版本与实际输入根数。公开行情源最多约 640 根日线，界面会提示预热长度与验证限制。MCP 和独立指标页不传行情快照时，由 FineRove 的行情服务准备输入。

## 私有计算服务配置

FineRove 进程需设置 `FINEROVE_NEO_BASE_URL`、至少 32 字符的 `FINEROVE_NEO_SIGNING_KEY` 与明确的实例标识 `FINEROVE_NEO_ISSUER`，也可保存在独立 `~/.finerove/env` 中并重启服务。远程服务必须使用 HTTPS；仅字面回环地址允许 HTTP。密钥仅保存在服务端，不进入前端或仓库。

驭潮进程在环境变量或自身 `.env` 中设置匹配的 `YUCHAO_NEO_SIGNING_KEY`、`YUCHAO_NEO_ISSUER`，以及 `YUCHAO_NEO_GRANTS_FILE` 指向独立授权 JSON 文件，并重启服务。文件按 FineRove 用户 ID 授权，例如：

```json
{
  "1": {
    "capabilities": ["neo.trend_histogram"],
    "expires_at": "2026-12-01T00:00:00+08:00"
  }
}
```

此处 ID 仅为结构示例，须对应实际账号。授权每次请求重读，撤销后下一次请求即拒绝；管理员也不绕过授权。只接受已结束日期的日线请求，最多返回 500 点。未配置服务时目录仍可查看，计算不可用。

## 金融 MCP

认证的 Streamable HTTP 入口为 `http://127.0.0.1:8098/api/mcp/finance`，提供两个只读工具：

- `list_neo_capabilities`：查看 NEO 能力目录、连接状态和验证状态。
- `evaluate_neo_indicator`：按证券、已结束日期、复权方式请求指标结果；当前仅趋势柱线已接入。

在支持 Streamable HTTP 和自定义请求头的桌面或服务端客户端中，设置上述 URL，并使用 `Authorization: Bearer <FineRove 登录访问令牌>`。访问令牌由 `/api/auth/login` 获取，过期后重新登录；不要在 URL、对话或工具参数中放入令牌。远程部署应使用 HTTPS。

计算参数示例：

```json
{
  "capability": "neo.trend_histogram",
  "instrument_id": "CN:SH:stock:600519",
  "period": "day",
  "adjust": "qfq",
  "end": "2026-10-30",
  "limit": 100
}
```

MCP 与页面使用同一个登录身份和私服账号授权，客户端不能指定其他用户、私服地址或签名密钥。未配置或未授权会返回工具错误，不生成替代值，也不清除有效登录。

首版为无会话状态服务，仅支持没有 `Origin` 请求头的桌面/服务端 SDK；浏览器直连会被拒绝，网页继续使用现有金融 HTTP API。专家运行时和微信/飞书的金融工具仍未启用，需先补全可信实际调用者身份；不借用专家所有者或管理员身份。
